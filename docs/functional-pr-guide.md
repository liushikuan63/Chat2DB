# 完整功能 PR 的拆分与验收

每个提交主线的 PR 应交付一个或少量完整行为，包含该行为所需的入口、参数校验、实现、数据／传输影响和回归测试。按功能拆分；跨前端、后端和存储的必需代码放在同一个 PR。后续 PR 可以依赖已经完整交付的功能 PR，不能依赖尚未提交的 helper、DTO 或目录层。

提交顺序从核心到边缘：先保证执行、事务和数据正确性，再完善任务生命周期与恢复、单表操作、多表与格式扩展，最后补充交互体验、桌面集成和运维能力。后续分支作为完整的增量补充；可以依赖已交付的核心功能，不能以“后续会补齐”为理由提交残缺入口。每个功能的必要测试和文档随该功能提交，不能延后到最后一层。

优先让生产差异控制在数百行可审查范围；分别统计生产、测试／fixture、文档／配置的新增和删除行数。超过该范围时说明最小依赖集合与无法进一步拆分的理由。不要通过压缩格式、隐藏生成文件、删减测试或拆开必需依赖来降低行数。

## 提交前检查

1. 固定实际 base/head SHA，检查工作区和现有改动。用该 PR 的实际源码树运行验证，或证明测试树与该源码树逐文件一致。
2. 沿真实入口检查依赖与行为闭环：UI／请求、校验、调用者、实现、序列化／存储、失败和取消。每个新引用都必须能在当前 head 或已经完整交付的前置功能中解析。
3. 运行项目 [AGENTS.md](../AGENTS.md) 对应门禁。Maven 显式启用测试并确认非零数量、失败／错误／跳过；前端执行相关测试、lint、Community build，并按实际改动验收交互。
4. 使用能区分正确与错误实现的回归。例如 SQL 事务不能只断言内部标志，还要检查真实数据库的提交／回滚结果；取消需要证明正在运行的语句停止，后续写入没有发生。
5. 对未运行的真实数据库、native 平台或提供方 CI 明确留空并解释条件。合并无冲突、编译成功、`BUILD SUCCESS`、历史日志或模拟接口不替代未执行的流程。
6. 检查最终差异、凭据和生成文件，再按授权提交／推送；回读远端 SHA 及 PR 的 title/body/head/base。存在确认缺陷或必需验证缺口时，保留草稿状态／明确未就绪，不称为可合并的完整功能。

## PR 说明

沿用 [仓库 PR 模板](../.github/pull_request_template.md)，让不了解聊天历史的审查者也能看懂：

- 用户操作或请求触发什么问题，改前／改后行为是什么。
- 当前 PR 包含的每项功能及其入口／关键文件；必要的已完整交付依赖。
- 生产、测试／fixture、文档／配置分别改变多少行；大差异的必要性。
- 实际执行的命令、被测 head、计数与结果，实际 UI／数据库证据及未执行项。
- 对公开接口、旧数据、失败前缀、重试／取消和恢复有什么影响；合理的回退边界。

旧目录分层 proposal 可以保留为历史证据和迁移清单。更新主线 PR 的功能边界时，保留旧内容的本地快照和提交历史，重写标题与说明，避免让旧层的测试结果被误认为新功能 head 的验收。

## 当前功能交付顺序

以下是从整合分支拆出的功能边界和审查顺序。只有逐项生成实际候选、核算差异并完成验收后才可提交主线；排队项目不代表已经交付。后续候选基于已合并主线或已验证完整的功能父分支。

| 顺序 | 完整增量功能 | 必须随行的依赖与验收 |
| --- | --- | --- |
| 1 | 可取消 JDBC 分块插入与 SQL 事务保护 | SPI、执行调用者、普通 CSV/Excel/JSON 失败前缀兼容；真实事务与取消回归 |
| 2 | 导入源文件的任务所有权和安全保留 | staging 服务、任务引用与清理、失败资源保护；任务活跃与过期孤儿对照 |
| 3 | 任务持久化、重启恢复与提交重试身份 | spec/checkpoint、文件存储、运行恢复；重启后状态和已提交前缀不丢失，重试不重复写入 |
| 4 | 单文件预览、映射与导入 | 上传、格式读取、旧参数兼容、服务/接口、单表界面；真实预览→映射→提交→结果 |
| 5 | 用户可见的任务取消与终态 | 核心取消资源、权限控制接口、任务界面；排队/运行/提交边界取消 |
| 6 | 并行导入准入与实际执行模式说明 | 资源快照、限制评估、执行入口、阻塞说明；不安全请求不能绕过限制 |
| 7 | 第三方导出 SQL 的安全兼容导入 | profiles/parser、风险扫描、事务/范围限制、提交入口；支持与拒绝 fixture |
| 8 | 多表依赖规划、分片与导入 | manifest/每源选项、依赖顺序、运行/恢复、完整向导；真实多表、坏行、取消和重试 |
| 9 | 可选 H2 任务存储 | provider、选择配置、迁移/恢复兼容；隔离存储迁移与重启 |
| 10 | 动态上传限额与交互完善 | 实际配置能力接口、服务/hook、累计选择校验；刷新限额与超额拒绝 |
| 11 | JCEF 来源准入与生命周期完善 | 原生 handler、renderer、取消查询、关闭/重启；来源准入与目标平台进程验证 |
| 12 | 集成 CI 与运维补充 | 已有功能的统一门禁与可复现操作；非零测试、缺失报告拒绝、head 绑定 CI |

相互独立的补充可以并行准备，但主线顺序优先核心功能。实际依赖检查若要求调整，应更新此表及对应 PR 说明，不以旧 `fn01–fn14` 目录层编号决定合并顺序。
